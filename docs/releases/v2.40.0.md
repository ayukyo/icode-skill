# ICODE v2.40.0 — 通用本地 MCP 同进程合并

默认 MCP 发行从 13 个服务收敛为 9 个。`icode-local` 用一个 Python stdio 进程承载 workspace、evidence、local-index、mcp-health 和 mcp-policy；设备、邮件、模型辅助及四个第三方服务继续独立运行。

- 27 个原工具增加 `workspace_`、`evidence_`、`index_`、`health_`、`policy_` 模块前缀，另提供一个静态聚合 `describe_capabilities`，共 28 个工具。显式参数、返回 schema、异步行为和读写 annotations 保持兼容。
- 模块按实际调用懒加载，列工具或读取聚合描述不扫描工程、不创建索引、不联网，也不启动五个子 MCP。原五目录保留为业务兼容模块，各自的配置与权限独立。
- 新发行清单 `mcp/servers.json` 管理九个默认服务，旧版本无清单时兼容原扫描方式。单装统一服务只处理其五个明确替代成员，不影响无关服务或未选宿主。
- 复用安装收敛器：先保存旧代码/配置的私有恢复快照，校验新注册后才退役已证明归属的旧节点、归档旧虚拟环境和缓存。业务代码、有效配置和活动数据保留；用户修改与未知归属报告冲突。
- profile 预检拒绝缺失、损坏、冲突或语义不明的配置路径，也保护显式引用的活动配置，避免发行文件覆盖其访问限制。运行时拒绝错误模块键和无效映射，不能因配置拼写错误扩大到默认路径权限。每次归档移动前重新检查活动配置、索引数据库与策略依赖。
- 策略仅增加物理 transport 映射，继续执行原逻辑模块的 step、condition 与 operation 规则；旧版外部策略无需改写权限正文即可解析新工具名。索引写入不会借统一服务获得原先禁止的权限。健康清单区分默认服务、兼容模块和规则目录。
- 直接安装与重装会补齐统一服务依赖的五个业务源码；保留旧配置、运行时和统一 profile，不复制私人配置或 `.env`。默认卸载采用同一九项清单，旧显式入口继续兼容。
- Windows 统一安装会验证真实 Python，优先复用显式解释器并支持 `py -3`；WindowsApps 空入口不能跳过预检，同一解释器贯穿环境创建与注册。

## 验证与能力边界

已在隔离 Linux 环境完成新旧模块组合回归，以及真实 stdio 的 28 工具与代表调用验证；Windows/Linux CI 继续执行新服务、替代迁移、策略权限和发行组件检查。核心发行仍遵守 200 文件预算。

每个原本启动五个通用本地服务的宿主会话现在只需一个进程；不同会话仍可能各启动一份统一服务。本版不引入全局 daemon，也不将目录数或静态清单直接当作整机内存收益。

实际宿主注册变化需重载或新会话。本机 Windows 曾出现原始 TCP 回环与空 asyncio 事件循环超时，旧服务也可复现；该主机运行边界与发布源码及 Linux 协议验证分别记录，不通过修改系统网络设置或伪造调用绕过。

## English summary

Consolidates five generic local MCPs into one lazy, in-process `icode-local` server with 27 namespaced legacy tools and one aggregate capability tool. The default catalog shrinks from thirteen services to nine. Migration preserves independent configuration and logical permissions, verifies new registrations before retiring owned replacements, and protects active data during runtime archival. Device, mail and third-party services remain separate.
