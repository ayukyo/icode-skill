# ICODE v2.33.0 — 环境诊断与验证登记衔接

本版针对重复出现的安装/注册漂移、Windows BOM 配置和现场证据登记遗漏，补齐诊断与交付摘要。复用现有 health、patch、verify 和验证账本，不增加现场状态机或免哈希通道。

## 只读环境诊断

- 新增 `python3 tools/mcp_doctor.py --json`，以及 `/icode status --doctor` 步骤入口；Windows 可使用 `py -3`。
- 识别外来平台路径、找不到的启动命令/入口、Windows shebang 包装器、缺失注册与导出条目漂移；命令名按条目或当前进程 PATH 解析。
- 显式 `--source` 后比较检测到或指定安装根的核心资源摘要。该结果只覆盖声明的核心资源，完整同步仍走官方脚本与既有校验。
- health MCP 增加 `diagnose_registration`；配置、目录和每个导出文件均应用 allowed_roots。不启动配置中的命令、不联网安装、不修配置、不输出参数或环境变量值。
- 安装/注册/会话分别报告。`static_ok` 不代表握手成功，工具在当前会话是否可用仍需真实发现与调用。

## BOM 与交付摘要

- Claude JSON 读取兼容 UTF-8 BOM；写入仍使用 UTF-8。真实坏 JSON、错误编码或非对象仍备份并拒绝覆盖，未知字段和其他 server 保留。
- 修复受管渲染器的 Ubuntu 依赖地址 404：改用固定日期的官方快照与官方归档地址，两个包的版本、长度和 SHA-256 保持不变并重新核对；仍由真实安装/渲染门禁验证。
- `icode_delivery.py` 新增 `environment_observations`，汇总已有 thinking trace 与 MCP 派生报告的降级/不可用信息，并进入 Markdown 摘要。历史重试按记录计数；缺失或坏文件明确待核实，不改变既有门禁和交付结论。

## 现场验证与兼容边界

- 自然语言续跑、verify 与 audit 明确实际阶段和 run/事件的收尾对账；新轮次使用唯一证据路径，保留旧产物与摘要。
- completed 后继续使用 patch/verify；已进入关闭流程的工单仍遵守 reopen/close-repair 的原合同。验证登记的幂等性不授权重放部署或 OTA。
- 历史交接文本先核对原始证据，模拟结果不作为实机通过，不自动升级 verified。
- 没有新增设备写入、在线表格回写、后台监控或 Windows/WSL DOCX 渲染支持；这些建议需要独立目标与验收。

使用方法和诊断范围见 [环境诊断与现场验证登记](../../references/environment_diagnostics.md)。源码与既有工单保持兼容；新 health 工具在同步后需重载对应 MCP 会话。

## English summary

This release adds bounded, offline registration diagnostics shared by a CLI and the existing health MCP. Core file fingerprints, registration shape and actual session availability remain separate observations. No configured command is spawned or repaired, and arguments and environment values are omitted from reports.

Claude configuration accepts a UTF-8 BOM while preserving corruption protection. Delivery reports expose recorded thinking/MCP degradation without changing gate decisions. Field follow-ups retain the existing patch/verify and verification-record lifecycle, immutable evidence and candidate bindings. Simulated observations do not certify physical-device acceptance.
