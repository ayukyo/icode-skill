# ICODE v2.37.0 — 通用工作流兼容与阻断恢复

本版修复验证登记与后续检查不一致、正常提交后的历史审查兼容，并提前报告后端能力边界。复用既有控制面，不新增公开命令、人工确认表或证据绕过选项。

- 验证记录与 workflow linter 共享敏感材料规则。中英文普通授权、安全说明不再依赖英文句式白名单；凭据字段、赋值、认证头和已知密钥材料仍拒绝。登记在锁与事务恢复前预检、发布前复检，错误不回显凭据值；合法历史说明无需改写受保护事件。
- 同 checkout、同原 base、实施契约不变且范围不缩时，正常线性前向提交可由后续完整、有效的当前原生审查覆盖历史检查。保留原报告和回执字节；新根、新 base、回退、改写、分叉、replace/graft、最新审查后漂移、伪造和失败重试仍拒绝。证明沿用64次线性提交边界，merge与超出范围的历史不自动接受。
- 无法可靠建立阶段状态时返回 unknown，保留写入保护，并报告具体工单、控制文件、JSONL行或预算原因与现有只读恢复入口。损坏历史不会被跳过；顶层及相关嵌套 metadata 的非对象形态也返回结构化诊断。
- action-policy 增加整组请求的能力预检，宿主可重复传入 --required-step，提前列出全部未支持步骤，并过滤不可执行的动作推荐。受保护 Git 当前仅接通 code inspection，仍需配对的 candidate provider 与 inspection factory；其他业务步骤的能力缺失不通过裸 Git 回退或重复授权解决。能力预检不等于权限或现场运行验收。
- 修正跨平台测试夹具：候选准备使用正常预算，单独模拟真实 artifact 读取到期；从现有 cc/gcc/clang 选择同一编译器贯穿真实构建与 provenance；阶段夹具统一使用规范化路径，兼容 Windows 临时目录的8.3别名。不修改产品时限，不用模拟替代真实编译。

## 验证范围

Windows 原生合并回归213项通过、1项跳过；受保护 provider 回归60项及101个子测试通过；最终阶段边界54项及37个子测试通过、2项跳过。新增阶段类型补测另在正式目录复跑；实际核心包完成能力预检、普通说明写入后检查一致、凭据拒绝且不写入/不回显的原生CLI验证。本机现有GCC实际编译与执行产物，并完成新ctime/旧mtime的真实验证登记。

符号链接用例因本机权限跳过。关联preview HTTP回环、serial fixture及大账本场景没有新增完整现场验收，不将其列为通过。敏感检测基于字段、明确语法和已知材料格式，不能保证识别任意无标记随机串或任意编码秘密。

CI增加Linux/Windows通用恢复回归，继续保留既有安装包、Windows UI和renderer资格检查。core、plugin-core、SkillHub与可选组件按同版本批次构建并附SHA256校验；轻量导入包保持不超过200文件。提供SkillHub包不表示已经上架或获得平台审核。

## English summary

Verification writes and workflow linting now share credential checks without a sentence whitelist for ordinary permission prose. Authenticated later reviews can cover bounded, linear forward commits while preserving historical receipts and rejecting rewritten or stale history. Unresolved stage state reports precise recovery diagnostics while retaining write protection. Action-policy checks all requested steps before work and exposes protected-provider gaps without raw Git fallback or new confirmation forms. Existing security, packaging and renderer qualification boundaries remain in place.
