# ICODE v2.46.2 — fast profile 源绑定修复

补丁版本。v2.46.1 发布后 `main` 上的 `Inspection helper software` 仍为红灯，本次修掉；fast 的 standard 回退路径不变。

- **失败原因**：`mcp/workflow-gate/gates.json` 的 `execution_profiles.source_sha256` 钉住 24 个 fast profile 共享源文件。v2.46.x 的文档更新改动了其中 5 个（`references/control_plane.md`、`dir_and_metadata.md`、`project_intake.md`、`thinking_core.md`、`worktree_isolation.md`），但哈希钉未同步。校验失败后 compact fast profile 按设计返回 `profile_validation_failed` 并回退 standard 路由，同时使 `test_execution_profile*` 等 11 个用例失败。
- **修复方式**：按 `sha256_utf8_lf` 重新计算 5 个文件的 LF 归一化摘要并更新哈希钉；profile 结构、锚点、requirement 规则文本均未改动。
- **影响面**：仅恢复 compact fast profile 的可用性与源绑定；standard/full 流程、控制面存储、候选侧库、出生与归档逻辑不受影响。

## 验证边界

在 WSL Ubuntu-22.04 按 `inspection-software.yml` 顺序复现：修复前 11 failed / 165 passed，修复后失败步骤 176 passed / 1 skipped；同工作流 fast admission 步骤 139 passed、候选存储步骤 300 passed / 54 subtests。`Inspection helper software` 已在修复提交上转绿；本版本资产按同一提交重建并校验 SHA256。

## English summary

Patch release fixing the remaining red `Inspection helper software` run after v2.46.1. The frozen `execution_profiles.source_sha256` bindings still referenced five shared reference files changed by the v2.46.x documentation updates, so compact fast profiles failed validation and fell back to the standard route while eleven profile regression tests failed. The five pins are now recomputed from the committed LF-normalized sources; profile structure, anchors and rule text are unchanged, and only compact fast profile availability is restored.
