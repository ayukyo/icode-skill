# ICODE v2.32.1 — DOCX 渲染器安装与发行修复

- 公共安装器与默认首次 Word 渲染自动安装固定版本、SHA-256 校验的受管渲染器。
- 渲染器及登记存储在独立用户运行时目录，升级、技能同步不会丢失登记；禁止系统 LibreOffice/Poppler 引擎兜底。
- 增加兼容性、文件和符号链接完整性校验、并发锁、离线缓存与失败处理；不覆盖损坏的已有运行时。
- 发行构建要求渲染器组件成套存在；真实安装、同步、Word 渲染和生成包验证通过后才允许公开构建或 Release 发布。
- 保留主干的 Claude Code、Codex、CodeBuddy、WorkBuddy 安装目标。

当前渲染配方支持 Linux x86_64、glibc >= 2.35、kernel >= 4.18、x86-64-v2，已在 Ubuntu 22.04 验证。一般系统动态库和中文字体仍为宿主依赖；Windows、macOS、ARM 暂未提供渲染配方，明确报告 visual_qa_pending。

发布前本地验证：25 项渲染器专项测试、15 项公开发行工作流测试及 20 轮官网检查通过；六份 Word 共 53 页回归与此前验收图像一致。远端检查和部署状态请查看本版本提交对应的 GitHub Actions，不将本地检查冒称远端 CI。

安装请按仓库 README 执行 `bash install.sh --client all`。Release 的 `icode-v2.32.1.tar.gz` 为完整技能资源包，内含安装入口 `icode/skills/icode/install.sh`；运行时依赖由安装器获取，归档不包含本机运行时、凭据或验收产物。第三方素材许可见包内 NOTICE，整包不额外重新许可。

后续正式版本复用 `.github/workflows/release.yml`：推送与源码版本一致的 `vX.Y.Z` 标签并提供 `docs/releases/vX.Y.Z.md`，渲染资格检查成功后创建 Release 及资源包。不覆盖已有 Release；官网由已授权的主干推送流程部署，标签工作流不额外发送社交平台公告。

## English summary

This patch fixes owned DOCX renderer installation and persistence across skill synchronization. Pinned official packages are verified before extraction; unsupported platforms remain explicitly pending. Public distribution and tag-triggered Release publication require real installer, sync and render qualification. Existing mainline WorkBuddy support is retained. Runtime binaries are installed separately and are not embedded in the skills archive.
