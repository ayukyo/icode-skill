# ICODE v2.44.0 — 实现克制准入与跨步骤口径一致性

本次更新把"防过度防御、拒绝提前抽象"收敛为编码期可执行的准入规则，并清理了 04_code 跨步骤引用错位，以及"异常/边界完备性"被误读为"必须为理论边界新增防御"的口径冲突。

- **04_code 新增第 11 条「实现克制」**：新增防御性检查/兜底/重试/并发保护前，必须能指出已观测的触发路径或计划内明确依据；无依据的防御按 B 档处理，在 `code_deviations` 记录并按反偷懒第 26 条取得用户确认、写入 `confirmed_B_fixes` 后再实施。急停/安全降级/资源释放/外部协议边界/跨信任域输入仍必须防御，且不得以"过度防御"为由删除既有保护。
- **抽象与复杂度克制**：单次使用且无既有复用、无契约/测试要求、无第二消费者的逻辑就近内联；既有可复用函数、跨层翻译纯函数、需要独立单测的逻辑仍必须提取。能单函数清晰表达的不强行拆分为多层/多函数。
- **跨步骤口径统一**：02_review 维度 7、05_deepcheck Fixed/Free、06_audit 代码质量/残留风险、01_plan §6/§10/接口误用预审、08_patch 编码与复检表均引用同一准入口径；同时修正 04_code 内部"第 8/9 条"、05/06 "日志第 7 条/优雅度第 9 条"等引用错位。
- **子仓提交口径**：SKILL、06_audit、worktree_isolation 明确 ICODE 不代执 commit；业务子仓与 super 仓库一视同仁，子仓 commit/merge 由用户手动执行。
- **全局指令同步**：Claude Code `CLAUDE.md` 与 Codex `AGENTS.md` 的"异常全覆盖"改为"按信任域分级覆盖"，并加入限定版编码克制规则；两份文件保持一致。

## English summary

Adds an implementation-restraint gate to the coding step: new defensive checks require an observed trigger path or an explicit plan basis, otherwise they are treated as tier-B work requiring user confirmation; safety-critical paths remain mandatory. Adds abstraction/complexity restraint, aligns review, deepcheck, audit, patch and fast contracts to the same rule, fixes stale cross-step section references, and clarifies that ICODE never commits, including business sub-repositories.
