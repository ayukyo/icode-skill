# ICODE v2.38.0 — 同机 AI 外包协作

新增独立 `icode-outsource` 技能及 `/icode outsource` 步骤。发起 AI 整理需求并输出绝对 `request.md` 入口，人工只转交入口；接单、消息、交付及接入通过同一工单关联，无需记忆内部编号。

- 标准库 Python 与 SQLite 维护单一事务状态、幂等回执、依赖、执行身份和消息确认。精确入口优先，不按“最新工单”猜测。
- 冻结声明范围内的实际源码字节（含未提交修改），物化到独立目录；预留修改范围，协调浏览器/设备等公共资源的独占及别名，保护内部锁命名空间。
- 冻结交付文件和证据；逐文件核对基线、保存备份及 journal，支持部分接入中断后恢复。发起端换会话需明确恢复绑定，旧会话不能继续操作。
- 接入后返工先核对已接入候选，再冻结新基线、更新 attempt 并准备新目录；历史交付、失败和证据保留。
- 修复 Windows 复评测试的换行证据构造：同一份原始字节生成 SHA-256 和完整行段，显式覆盖 LF/CRLF；错误 hash、正文或换行继续拒绝且不写回。
- 发布流程增加 Windows/Linux 外包资格测试，与原有 renderer 检查共同作为正式 Release 前置门禁。
- 网站、品牌及发布维护工具移入既有 `support` 组件，完整包继续保留；外包运行文件保留在核心包，核心插件保持 200 文件预算。

## 验证与能力边界

本机新增软件测试：Windows 99通过、1项因账户无符号链接创建权限跳过；WSL/Linux 91通过、9项Windows专属用例跳过。另有 inspection/crosscheck 相关120项Linux回归通过，Windows LF/CRLF 两项原用例通过。线上资格以本版本提交的实际 Actions 结果为准。

资源预留约束通过协调工具的参与者；独立目录与交付检查不是 OS 沙箱。监测是有界只读查询，不自动唤醒模型。真实双宿主 AI、浏览器和设备仍需按项目授权及现场证据验证。外包生命周期不自动推进父 ICODE 工单状态。

发行继续使用既有完整归档、core、plugin-core、SkillHub及可选组件格式，附 SHA256 清单。用户配置保持独立；同步文件不会热重载运行中的宿主或 MCP。

## English summary

Adds same-machine outsourcing between independent AI tools, using a precise request-file handoff, atomic claims, threaded messages, scoped isolated source copies, cooperative resource reservations, immutable deliveries and restartable integration. Integrated rework starts from a freshly verified baseline. Exact-byte LF/CRLF inspection evidence remains strict. Windows/Linux outsourcing qualification and the existing renderer checks gate release publication.
