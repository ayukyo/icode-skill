# ICODE v2.45.1 — Linux CI 压缩夹具修复

补丁版本。v2.45.0 发布后 `main` 上的 `inspection-software` 工作流仍是红灯，本次把它修掉；产品行为无变化。

- **`test_storage_compaction` 夹具修正**：`legacy_ticket` 只带一个最小 seed，序列化后 metadata（540B）反而小于事件账本（614B），正好踩中 `compact_ledger_dominates` 护栏——产品按设计拒绝 `--apply`，测试却期望成功。Windows 因换行字节差侥幸通过，Linux 上稳定失败。该失败在 v2.45.0 之前的 `eadf6eb` 上同样可复现，属既有缺陷。现在夹具补入 8 条 `requirement_points`，稳定落在「metadata 大于账本」区间，也就是 compact 设计针对的真实场景。
- **护栏用例改为真实撑大账本**：`test_ledger_dominated_ticket_requires_force` 不再把 metadata 重新序列化成紧凑 JSON（那依赖两种写法的字节差，属平台相关巧合），改用 `event` writer 追加审计事件把账本撑大。
- **CI 触发路径补齐**：`inspection-software` 的 `paths` 增加 6 个 storage 测试与新增的 `test_step_port_protection_unit.py`，使这些用例的改动会真正触发该工作流，不会再出现"改了测试但工作流不跑"的盲区。

## 验证边界

在 WSL Ubuntu-22.04（与 CI 同发行版）复现并验证：修复前整条步骤 `2 failed / 298 passed`，修复后 `300 passed / 0 failed`；Windows 上同一步骤 `290 passed / 10 skipped`（跳过项为符号链接能力探测）。推送后线上 `inspection-software` 在 `c577e1d` 转为 success，`public-site` 同步 success。

## English summary

Patch release fixing a Linux-only CI failure left over from before v2.45.0. The `test_storage_compaction` fixture produced metadata (540 B) smaller than the event ledger (614 B), which correctly tripped the `compact_ledger_dominates` guard, so `compact --apply` was refused while the test expected success; Windows passed only because of line-ending byte differences. The fixture now carries enough metadata to sit in the regime compaction targets, and the guard test grows the ledger through the real event writer instead of relying on JSON serialization differences. The inspection workflow's `paths` filter now also lists the storage tests so edits to them actually trigger the workflow.
