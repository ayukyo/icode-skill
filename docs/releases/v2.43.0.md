# ICODE v2.43.0 — fast 合同精简与 fast/start 共用执行提速

fast 按来源版本校验后的适用合同执行；fast 与 start 优先复用既有批量登记，并可在同一次宿主调用中顺序完成已确定的机械收尾。六阶段、必要审查、默认 L2 思考、适用测试和原有门禁保持。

- 在既有策略模块提供只读 execution profile。policy2 有效 fast 的 step-start 与精确重放响应可返回对应阶段原文、职责来源、摘要和登记指引；固定绑定 24 份 Markdown、六阶段和 17 个职责 ID。规则版本、锚点、路径或预算不符时回到原步骤适用正文，保持有效模式，不绕回失效 compact 导航。
- fast 必要职责收敛到同一规范入口，主步骤保留原 full 正文及条件合同。投影不写入工单事件，不产生授权或已读证明。full、历史 fast 与辅助步骤继续原规则路径，start 保留多轮审查、对抗和 Reverse/Fixed/Free。
- code、Reverse、Audit 及 full 的适用阶段，实际独立 Read 后优先使用已有 `--paths-json` 批量登记；逐成员 hash、完整范围、专项、漂移和回执条件不变，旧 `--path` 继续支持。
- fast/start 共用短收尾示例：在一个外层工具调用中串行执行原 artifact/check/finish/transition，首个失败即停。各原生事件、检查和 writer 保留；中断后核验 trace，仅续未完成后缀，不新增父事务、批量写入协议、MCP 或常驻进程。
- 源版本、模式、幂等、回退、路径/符号链接/junction、CRLF、生产门禁、旧接口及核心包集成均加入回归；核心导入预算保持 200 文件。

## 测量与验证边界

Windows 原生隔离机械测量，12 文件、三轮交错：fast 登记中位耗时 7.43→0.62 秒，full/start 共用登记路径 7.44→0.61 秒；每阶段 CLI 登记调用 12→1，全部文件及 hash 仍登记。六阶段 compact 正文合计 13,758 bytes，含版本引用的 JSON 合计 55,128 bytes；原六份步骤文件合计 289,210 bytes。必要共享/条件规则、业务源码与原始证据的加载另计。

上述数字只反映机械登记与规则投影，不是完整模型开发提速比例。完整 fast/start 成对模型耗时、真实设备及盲测缺陷检出率尚未验收；独立审查和测试责任继续保留。

本地 Linux 相关矩阵：989 passed、1 平台跳过、172 subtests passed；Windows 广回归：260 passed、2 符号链接权限跳过、42 subtests passed，另有26项原生集成测试通过。规格及质量两轮独立审查均无P1/P2，各自另跑136项新增测试；平台跳过不计作已通过。

更新完整安装后，运行中的 AI/MCP 会话应正常重载或新建会话，以采用新版指令。

## English summary

Adds source-bound compact fast instruction views and promotes existing batch inspection registration for both fast and full workflows. Preserves original workflow authority, independent reads, reasoning tiers, tests, evidence gates and event identities. Ordinary closeout commands can run sequentially in one outer tool call with fail-fast, trace-based recovery; no new MCP, daemon or transaction protocol is introduced.
