# ICODE v2.32.3 — 串行证据阶段门禁与受保护 Git 贯通

本版把「阶段程序 + 证据包」纳入受控写入契约，并让受保护 Git 读取端口贯通候选、历史、派发、构建启动、验证记录与代码审查的只读上下文。

## 串行证据与阶段程序

- 新增证据合同、阶段程序与验证证据三组 schema；阶段登记、计划预览与修订、绑定、审查、确认走独立生命周期，阶段计划支持修订与阶段合并。
- 受保护命名空间（stage program、stage binding、串行声明、视觉审查、证据审查）只允许专用写入者更新，普通写操作一律拒绝改写。
- host runner 支持串行阶段执行与 UI 预览；串行证据、媒体路由与宿主适配的边界见 `references/serial_evidence_stages.md`。
- 未启用阶段的项目保持原有行为；阶段投影为只读视图，不产生写副作用。

## 受保护 Git 贯通

- 候选上下文、历史、派发、构建启动、验证记录、动作策略与代码审查统一通过宿主提供的受保护 Git 读取端口取源，只读查询不落盘。
- 缺少受保护上下文时明确拒绝，不回退到未受保护的原始 Git 调用；无 provider 的普通路径保持原有语义。
- 端口根标签在 Windows 上保持 Git 风格的字面路径，避免反斜杠转义引起的身份不一致。

## 候选与检查工具

- 候选支持原生批量处理与 LFS 指针识别，批量结果的候选身份与单次捕获一致。
- inspection 复用冗余声明并细化报告生成；crosscheck 增加陈旧容器恢复与原子 manifest 写入。
- Windows 上优先使用 `py` 启动器解析受控解释器。

## 跨平台与可移植性

- 技能同步改用重命名回收运行时目录，不再复制 `.venv`，减少同步中断留下的半成品。
- 工作流报告、控制面线格、交付 Markdown 与回归门禁目录统一按 UTF-8 读写。
- 修复 Windows 路径、超时与测试夹具的多处可移植性问题，本地 MCP 与 inspection 夹具在两种平台上使用同一套规范化路径。

## 修复：阶段门禁不再误伤普通工单

- 普通（非阶段）工单的未完成事务、损坏账本或过期 provider 上下文，不再被阶段发现包装成 `stage_gate`；相应错误恢复为 `candidate_transaction_pending`、`event_chain`、`candidate_provider_context` 等业务门禁。
- 阶段项目的 locator 丢失、预算、超时、符号链接与并发读竞争仍然显式失败，不会因为上述放行而绕过阶段授权。

## 升级说明

- 源码版本以 `SKILL.md` 的 `**版本**` 行为准；安装执行 `bash install.sh --client all`。
- 既有工单与 metadata 保持兼容；未启用阶段的项目无需迁移。
- Release 的 `icode-v2.32.3.tar.gz` 是完整技能资源包，内含安装入口 `icode/skills/icode/install.sh`；归档不包含本机运行时、凭据或验收产物。

发布前本地验证：candidate provider 契约 B1–B3f 共 126 项、阶段验收/合并/发现共 79 项通过；渲染资格与发行包由标签工作流在真实安装与渲染链上验证。远端检查与部署状态以本版本提交对应的 GitHub Actions 为准，不将本地检查冒称远端 CI。

## English summary

This release makes stage programs and evidence bundles part of the controlled-write contract, and routes candidate, history, dispatch, build-start, verification-record and code-inspection reads through the host-provided protected Git port.

Stage registration, plan revision, binding, review and confirmation have their own lifecycle, with consolidated stages and dedicated writers for protected namespaces. Tickets without a stage program keep the previous behaviour, and stage projection stays read-only.

Candidate capture gains native batch handling and LFS pointer detection; inspection reuses redundant declarations; crosscheck recovers stale containers and writes an atomic manifest; Windows prefers the `py` launcher. Skill synchronization reclaims runtime directories by rename instead of copying `.venv`, and reports, control wire, delivery Markdown and gate catalogs are read and written as UTF-8 on both platforms.

A regression that turned an ordinary ticket's pending transaction, damaged ledger or expired provider context into `stage_gate` is fixed: those cases now report their own business gates again, while stage locator loss, budgets, timeouts, symlinks and read races still fail closed.
