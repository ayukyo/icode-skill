# 根因树模板（防"停在症状层"）

> **用途**：`/icode log` 阶段3 对抗根因分析时，分析师提假设**必须填本模板**，确保根因追问到触发层而非停在症状层。3 层都 confirmed 才算真 confirmed。引用 [steps/log.md](../steps/log.md)「根因树 3 层假设链」+ [references/adversarial.md](../references/adversarial.md) 对抗裁决。

---

## 责任主体核验（R1，每个假设必填）

每个假设（触发/机制/保护层）必须标注**动作主体**——谁执行了该动作 / 谁负责该缺失：

- 动作主体 A：<模块/函数名 + 该主体自己的日志行（日志行须同时含动作与 reason/id）>
- **判定**：断言"X 执行了动作 A"，必须有 X 自己的日志行同时含动作与 reason/id；**只有状态变了、却无主体日志 → 写 `主体未定`，不得归因**。
- 机制层传导链的**每个环节**同样须标注动作主体（谁执行了这一跳）。

---

## 根因树 3 层假设链

### 1. 触发层（底层 root cause）

**问题**：什么初始事件导致了问题？

- 假设 H1：<填底层触发事件，如"某 SDK/模块同步 I/O 阻塞跨线程锁">
- 动作主体 A1：<谁执行了触发动作 + 该主体自己的日志行>
- 证据指针 E1：<日志行 节点+时间+原文 / 代码行 file:line / 辅助文件 时间戳+数据>
- 置信度：<高/中/低>
- 验证方法：<grep 定位符号 / Read 实读 / 辅助文件 Read 实证>

### 2. 机制层（中间传导链）

**问题**：触发层 → 现象的传导路径？

- 传导链：H1 → <环节1> → <环节2> → <环节3> → 现象
  - 例：锁未释放 → 关联锁被牵 → 高频线程被堵 → 状态冻结
- 每个环节的证据：
  - 环节1：<证据>
  - 环节2：<证据>
  - 环节3：<证据>
- 置信度：<高/中/低>

### 3. 保护层（为什么没拦住）

**问题**：为什么系统没拦住后果？

- 假设 H3：<填保护层缺失，如"消费侧无状态时效门">
- 动作主体 A3：<该由谁拦住（责任模块/函数）+ 其日志或缺失证据>
- 证据指针 E3：<代码行 file:line / 日志行>
- 置信度：<高/中/低>

---

## 裁决标准

- ✅ **3 层都 confirmed** → 根因 confirmed
- ⚠️ **只 confirm 保护层，触发层 needs_more_evidence** → 整体降级 `needs_more_evidence`（诚实不完整）
- ❌ **只 confirm 机制层** → 降级 `needs_more_evidence`

---

## 质疑者追问清单

| 质疑者 | 必须追问 |
|--------|---------|
| 证据质疑者 | 触发层证据是否真在原文？证据指针是否可回指？ |
| 替代解释者 | 是否有其他触发层假设？触发层是否真的是底层（会不会还有更底层）？ |
| 充分性质疑者 | 机制层每个传导环节是否有证据？是否有断链？ |

## 自检

- [ ] 3 层假设链都填了（非空）
- [ ] 每个假设有动作主体（含主体自身日志行）；无主体日志 → 标 `主体未定` 未归因
- [ ] 每层有证据指针（日志行/代码行/辅助文件）
- [ ] 触发层经 grep 定位符号 + Read 实读验证（有可索引源码时）
- [ ] 上游假说已扫（TB 评论 + 历史工单），继承/否决有留痕
- [ ] 裁决标准已对照（3 层 confirmed 或诚实降级）
