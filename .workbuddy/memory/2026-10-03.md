## 契约测试在沙箱下偶发 SIGTERM 的排查与修复（收尾 2026-10-02 的 WorkBuddy 工作）

- 现象：WorkBuddy/CodeBuddy 四套契约测试断言全过（如 `11 passed, 0 failed`），但进程被 SIGTERM 杀掉 exit 1，且 `mktemp` 目录残留
- 两个叠加根因：
  1. **mktemp 路径污染**：宿主 `TMP=C:\Users\...`（反斜杠），裸 `mktemp -d` 返回混合斜杠路径 `C:\.../tmp.xxx`；`rm -rf` 这种路径被沙箱 safe-delete 拦截。修复：钉住模板 `mktemp -d /tmp/icode_*.XXXXXX`（与仓库既有 control-plane 测试惯例一致）
  2. **大目录删除超时**：apply 用例物化 ~2300 文件/170MB，同步删除需 ~100 秒，沙箱对 rm 进程有时长管控直接 SIGTERM——**与路径风格无关**，纯 `/tmp` 路径也会被杀。修复：EXIT trap 后台化 `rm -rf "$TMP" >/dev/null 2>&1 &`
- 排查手段沉淀：
  - `bash -x` + stderr 重定向看最后执行点（注意：SIGTERM 时 trap 的 trace 也会写进 log）
  - 残留目录大小/文件数（`du`/`find | wc -l`）+ 计时 `rm`（`time`）定位"删除慢"这一非直觉根因
  - 被杀进程的变量在后续命令中不可见（每次 Bash 工具调用是新 shell），需从日志文件读结果
- 最终结果：四套契约测试 exit 0 全绿（WB sync 11、WB mcp 5、CB sync 15、CB mcp 4）+ `test_tool_support_progress.py` 5/5
- 遗留注意：后台化清理会留下孤儿目录（本机跑完测试后可 `rm -rf /tmp/icode_*` 收尾）；正常 CI/Linux 上同步删除很快，不受影响
