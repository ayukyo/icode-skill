## 修复 test_tool_support_progress.py 的 symlink 特权设计

- 用户判断正确：测试用 `Path.symlink_to` 在临时 PATH 注入命令是错误设计——Windows 创建 symlink 需要管理员/开发者模式（WinError 1314），且测试语义只要求"命令存在于 PATH"而非"是真链接"
- 替代方案：bash 转发脚本 shim（`#!/<abs-bash>` + `exec <abs-exe> "$@"`），纯文本文件、零特权。已验证 MSYS bash 接受 `C:/...` 风格 shebang（正好匹配 `Path.as_posix()`）
- 关键细节：
  - bash 自身被父进程（Python CreateProcess）直接启动，必须是真实 .exe，不能是 shim 文件（CreateProcess 不认 shebang）
  - 子进程 PATH 只含临时目录时，shim 的 shebang/exec 必须用绝对路径，否则找不到 bash
  - env 的 PATH 值必须 `str(directory)`（Path 对象会报 "environment can only contain strings"）
- 结果：`test_tool_support_progress.py` 5/5 全绿，本机无管理员权限
