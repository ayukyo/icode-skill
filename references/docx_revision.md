# 已有 Word 修订与保持检查

适用于用户反馈“某章看不懂”“图有误”“颜色不统一”等已有 DOCX 修改。先读目标文件，不用生成目录中的旧副本代替当前实际文件。

## 修改前

1. 确认用户指定的文件集合、输出位置和实际版本，读取正文、表格、图片及配套源文/manifest。某一章或图的反馈默认只修改该处及必须同步的图注/引用。
2. 在交付目录的备份/审计子目录保存原 DOCX、源文、manifest 和图片，不删除旧版本。在候选文件上修改，检查后才更新目标。不存在配套 Markdown 时，从当前 Word 保留可审阅的正文快照，不要求用户重新提供。
3. 写下本次允许修改的章节/图片和必须保留的内容：模块及配色、公式、坐标、单位、关键参数、接口、条件、其它章节。先理解用户认为不清楚的地方，避免把“看不懂”自动解释为“细节都删掉”。

## 修改时

将拗口的模块名改成“谁做什么”的句子，但保留正式名称与源码对应；删重复表述，不删解释因果所必需的中间步骤。需要新增原理时先核对代码和已有说明，SDK可见部分与不可见固件的通用原理分别表达。

图示沿用当前共享模块配色和图例。只换必要对象或布局；其它图不顺手重画。对图的修改也同步源图、脚本、图注和正文引用。坐标/公式图特别检查原点、各轴、单位和输入示例，不能只保留数字例子却删掉空间含义。

Word有样式、页眉页脚或复杂表格时优先局部编辑，避免抽取纯文本再重建整份文件丢失格式。原源文为输入时保持它不动，修订稿另存；作为维护源文更新时先保存旧快照，并明确将它与Word成对维护。

## 对照检查

```bash
"$DOCX_PYTHON" tools/docx/compare_docx.py before.docx candidate.docx \
  --allow-section "5.1 从像素到空间坐标" --allow-figure 5 --report revision.json
```

`--allow-section` 是两版中唯一存在的完整 Word 标题；包括该节及子节正文，但**不会自动允许图像改变**。`--allow-figure` 是文档中第几次嵌入图片，从1开始，不是图注中的编号。分别列出两类修改，避免整章授权掩盖同章其它图被替换。

工具检查允许区域之外的正文、表格、公式文字、图像 hash、页眉页脚文字；未知/重复标题或错误图片序号会报错。修订报告保留所有文字和图片差异、删除的文字项。逐项审读删除项，尤其是坐标、单位、公式、条件和接口：在允许区域内被删除也不等于合理。

整个章节改标题、重排目录或全文重写时可用 `--report-only` 获取差异，不把它的退出码0当成保持检查通过。Word格式、布局、图内文字和原理正确性不属于该工具自动验证的范围，仍须读图和最终页面检查。

## 最终交付

维护真实 `input/output` 路径与 hash、`source_images`、`source_map`；不要仅刷 hash 来掩盖内容不同步。需要的新来源用 `verify_sources.py` 留下可回查记录，然后跑 `inspect_docx.py`，要求图示时加 `--require-diagrams`。

候选检查通过后保存到最终目标，再对最终文件渲染并查看所有页面。比较候选和目标 hash，确认保存的是已检查内容；最终位置的 manifest 路径也要更新并再次检查。渲染报告与本次 Word/页面 hash 不一致时，重新渲染，不能沿用旧的 `page_review`。

多文档请求逐份记录完成情况，未修改的文档可比较 hash 确认未变。收尾只说明主要变化、检查结果与未验证项，不把全部备份和审计细节塞进正文。
