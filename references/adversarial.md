# 对抗分析模式（共享规则）

> 本文件是 icode 对抗分析的共享规则（分析师+3质疑者+裁决优先级+诚实降级）。步骤2 审查 issue、入口 log 根因分析，均复用本模式。各步骤文件只声明"分析对象"（issue/根因假设），其余对抗流程引用本文件。

## 为什么必须对抗

单视角结论存在确认偏误风险（自己提的假设，容易"看着像对就收"）。只有当独立一方尝试反驳却反驳不倒，结论才可信。未经对抗的结论视为"待验证"，不计入收敛判据。

## 角色分工

用 `Agent` 工具 spawn 3 个独立质疑者（**必须独立 spawn，不得由主代理自行扮演**，避免自我背书）。三视角分工：

| 质疑者 | 视角 | 攻击点 |
|--------|------|--------|
| **证据质疑者** | 引用的证据真在原文里吗 | 核对证据指针指向的计划章节/代码行/日志行是否真实存在、是否断章取义、是否误读时间戳/上下文 |
| **替代解释者** | 有没有别的原因能解释 | **必须提至少 3 个竞争假设**（除非领域证据已穷尽并标注降级到 1 个）：该结论描述的"问题/根因"是否其实是正常行为/另一模块引起/误读？能否被推翻？ |
| **充分性质疑者** | 现有证据够不够 | 结论是否被证据充分支撑？还缺什么证据才能定论？ |

### spawn 规格要求（强制，防子代理失败）

每个质疑者 spawn 时**必须**满足以下规格，否则极易失败（实测痛点：默认/误用 Explore 子代理 → 只调研不裁决 → 调研阶段耗尽额度被截断、只返回开场白）：

0. **先加载 Agent 工具**（防"新会话 deferred tool 未加载误判 no_spawn_env"）：调 `ToolSearch(query="select:Agent")` 取 Agent 工具 schema 并加载。加载成功 -> 继续后续 spawn 步骤；加载失败（ToolSearch 返回无命中）-> 走「环境无 spawn 工具场景」降级。**禁止跳过 ToolSearch 直接判定 no_spawn_env**--Agent 是 deferred tool，新会话初始工具列表不含，必须主动加载。**必须用 `select:Agent` 精确加载**（关键词搜索如 `"Agent spawn"` 会漏项，实测只返回 TaskOutput 等非 Agent 工具）

1. **`subagent_type: "general-purpose"`**——**禁止用 `Explore`**（Explore 是只读搜索代理，擅长定位代码、不擅长裁决判断，长指令下倾向先调研后输出、被截断在调研阶段）
2. **用 `schema` 参数强制 StructuredOutput**——子代理必须调用结构化输出工具返回如下对象，不得输出长篇自然语言调研报告：
   ```json
   {
     "verdict": "confirmed | refuted | needs_more_evidence",
     "reasoning": "裁决依据（≤200字，必须含证据回指）",
     "evidence_ref": "回指到具体 file:line / 计划章节 / 日志行",
     "competing_hypothesis": "仅替代解释者必填：≥3 个竞争假设（领域穷尽可降级到 1 并标注）"
   }
   ```
3. **指令开头强制约束**：「直接输出裁决，读文件范围仅限喂你的路径，不要长篇调研。先给 verdict 再给依据。」

## 输入契约（喂给每个质疑者的内容，三份相同）

- 分析对象所在文件路径（计划/代码/日志）——让质疑者自己读，**不喂主代理的推理过程**
- 待验证的清单（issue 或根因假设），含其证据指针
- 指令：「独立读文件判断每条结论，返回裁决 + 具体反驳/支持依据 + 行回指。默认怀疑，证据不足时判 `needs_more_evidence` 而非 `confirmed`。」

> **独立性硬约束**：质疑者只能拿到"文件路径 + 结论清单 + 证据指针"，严禁把主代理推理链/分析过程原样塞给质疑者当既定事实。质疑者必须自己读文件独立判断，否则对抗形同虚设。

> **Freshness（跨轮隔离）**：每次对抗 spawn 的 3 质疑者都是**全新 Agent 实例，零上下文继承**，且**互相隔离**。主代理组装本轮 prompt 时禁止注入：①上一轮/历史轮次质疑者的裁决、依据、Agent ID；②log 阶段对抗的**裁决过程**。唯一允许注入的是**已定案的最终结论**——且仅当本轮分析对象正是该结论时（如步骤 2 复用 log 根因结论场景），此时注入的是"待验证对象本身"而非"别人的裁决"。
>
> **为什么**：质疑者若看到"上轮判了 confirmed"，会产生锚定跟随（顺着已确认表态），对抗退化为形式；质疑者互相看到对方的裁决同理。freshness 与"独立性硬约束"的区别：后者防"主代理把自己的推理塞给质疑者"，前者防"历史裁决污染本轮质疑者"。

> **Anti-coaching 措辞禁令**：组装完质疑者 prompt 后，逐句扫描以下 stop-phrases，命中即**删整句再发**：`已验证` / `已确认` / `证据充分` / `重点核对` / `无需质疑` / `不算问题` / `不是缺陷` / `建议采纳` / `主代理倾向`。**例外**：机制声明不受限（如"2.4 实证项不在此清单"这类对待验证对象的**范围说明**，不是对具体项的**价值预判**）。
>
> **为什么**：待验证清单已含 `suggestion`/`rejection_risk`，主代理极易顺手写"这条证据充分你快速过一下"或"这条只是小问题"——质疑者带着"主代理希望我怎么判"的姿态读文件，对抗即空转。禁令只针对预判**价值**，不限制喂**事实**（文件路径/证据指针/竞争假设要求）。

## 零待对抗快速通道

若分析对象为 0 条需对抗项（全无问题，或全部已实证无需对抗），跳过本步骤，直接置 `adversarial_verification = null`，进入产出写入。不得为空清单 spawn 质疑者浪费资源。

## 显式等待 + 超时机制（防"主代理未等子代理跑降级"）

**触发条件**：spawn 3 质疑者子代理后，**主代理必须等到子代理返回 verdict 才能进入裁决/降级流程**。实测发现"异步 spawn + 主代理未等待直接 mtime 监控"会触发降级路径误用——子代理实际仍在跑，主代理已按"未返回"标 `[未验证-子代理对抗失败]`。该标签应留给「确认失败」的子代理，不得给「还在跑或返回晚」的子代理。

**等待契约**（强制）：

1. **spawn 模式**：用 `Agent` 工具**同步** spawn（`run_in_background: false`）；异步模式必须**显式调 `TaskOutput`** 等结果，**禁止 spawn 后不等待直接进入下一步**
2. **超时阈值**：默认 `TIMEOUT_SECONDS = 120`（可由 `.ico_metadata.json.task_timeout_seconds` 覆盖）。子代理未在超时内返回 verdict → 视为「超时 → 触发重试 1 次」（不是"子代理失败"，也不是"环境无 spawn 工具"）
3. **超时触发重试 1 次**：超时主代理按"换措辞 + 可换 subagent_type 兜底（general-purpose → claude）"再 spawn 一次同一质疑者；二次仍超时或仍无 verdict → **进入**「子代理失败处理」失败链路（标 `[未验证-子代理对抗失败]`）
4. **timeout 与 verdict 截断区分**（**防误用降级**）：
   - `timeout`：spawn 句柄超时未返回 → 走第 3 步重试 1 次
   - `verdict 截断`：120s 内返回但 verdict 字段缺失/截断只剩开场白 → 走「子代理失败处理」第 1 步「检测失败」（不计超时）
   - **禁止用 verdict 截断触发"环境无 spawn 工具"路径**——后者只允许在 spawn 调用本身就返回错误（如工具不存在）时使用
5. **判定状态四态枚举**（写入 `adversarial_verification` 字段，便于审计追溯）：
   - `sync_ok`：同步等 verdict，120s 内返回
   - `timeout_retry_used`：触发 1 次重试
   - `still_failed_after_retry`：重试后仍超时/无 verdict
   - `env_no_spawn`：spawn 调用本身不可用（结构性，非 transient）
6. **TIMEOUT_SECONDS 边界与兜底**：
   - 默认值：`120` 秒，可由 `.ico_metadata.json.task_timeout_seconds` 覆盖（缺失视为 `120`，字段定义见 [dir_and_metadata.md](dir_and_metadata.md)「`task_timeout_seconds` 字段」段）
   - 非法值兜底：`task_timeout_seconds <= 0` 视为非法 → 静默回落 `120`（防误配 0 导致瞬时超时误降级）
   - 下限建议：不低于 `30s`（过短会过早触发重试链路，浪费 spawn 资源）

> **为什么必须显式等待**：等待机制把"未返回"与"确认失败"明确分开——前者是 spawn 链路正常但慢，后者是 spawn 完成但输出不可用。两条路径用不同降级标签 + 不同后续处理，混用会让降级语义失效。

## 子代理失败处理（重试→降级，绝不自演）

实测痛点：质疑者子代理偶尔失败（返回空、截断只剩开场白、schema 不符合、超时）。**禁止以"子代理调不通"为由改由主代理自演裁决**——主代理自演 = 自己提的结论自己质疑自己 = 既当运动员又当裁判，确认偏误会让它倾向确认自己的结论，对抗形同虚设（违反 anti_laziness.md 第9/14条"质疑者不得主代理自演"）。

**正确失败处理链路**（按顺序）：

1. **检测失败**：子代理返回空 / 无 schema 结构 / 无 verdict 字段 / 只剩开场白无裁决 → 判定本次 spawn 失败
2. **重试 2 次（治"子代理失败未重试就降级"）**：
   - **第 1 次重试**：重新 spawn 同一质疑者，**换措辞**（强化"先给 verdict 再给依据、读文件范围仅限喂你的路径、**必须返回 JSON verdict 不得输出长篇调研报告**"），subagent_type 不变（仍 `general-purpose`）
   - **重试前强制**：每次重试前**必须先 Read [anti_laziness.md](anti_laziness.md) 第 8 条**确认对抗独立性（防主代理自演倾向在重试时复活）
   - **第 2 次重试**：第 1 次重试仍失败 -> **强制换 subagent_type**（`general-purpose` -> `claude`），再 spawn 一次，prompt 同样含"必须返回 JSON verdict"约束
3. **重试 2 次仍失败 -> 诚实降级**：该条结论的对抗验证置为**未完成**，按裁决优先级的"兜底"档处理--降级为 `needs_more_evidence`，标 `[未验证-子代理对抗失败]`，计入 `pending_verification`，**绝不伪造 confirmed**
4. **留痕**：在 `adversarial_verification` 字段记录"子代理对抗失败，已重试 2 次（含 1 次换 subagent_type）仍无果，诚实降级为待验证"，附失败质疑者角色 + 失败现象 + 两次重试的 subagent_type

> **为什么宁可降级也不自演**：诚实承认"这条没验成"比"自己点头说过了"可信。`needs_more_evidence` 让步骤3定稿时知道这条需重点复核；伪造 `confirmed` 则把未经独立验证的结论混入定稿，埋下隐患。对抗失败是"少验了一条"，自演是"骗自己验过了"——后者危害更大。

### 环境无 spawn 工具场景（与 spawn 失败不同）

**判定**：当前 icode 环境没有 Agent spawn 能力（无 Agent 工具 / Task 工具不可用 / 会话类型不支持子代理）——这是**结构性不可用**，不是临时失败（不是网络抖动/截断/超时等可重试的 transient 错误）。

**规则**（区别于上方 transient 失败的重试→降级两阶段）：

1. **不重试**——环境无工具，重试无意义
2. **诚实降级**：标 `[未验证-环境无spawn工具]`（**非** `[未验证-子代理对抗失败]`，区分结构性不可用 vs 临时失败）
3. **产物文件强制明示**（降级了但用户没看到标记，不知道核心结论未经独立验证）：
   - `log_analysis.md §6` 子章节标题**必须**写 `### 6.X [未验证-环境无spawn工具] <质疑者角色>`，不得隐藏在正文里
   - `log_analysis.md §0` 一句话定性后**必须**追加一行 `> ⚠️ 本单判断性结论未经独立子代理对抗（环境无 spawn 工具，按 adversarial.md「环境无 spawn 工具场景」诚实降级）`
   - **不得不标记默认为已对抗**——无标记的 §6 被视为"主代理偷懒未对抗"而非"环境不可用"
4. **主代理代行有条件**（**`no_spawn_env` flag 严格门控**，不同于自演）：
   - **前置 flag**：`no_spawn_env = true`（环境结构性无 spawn 工具）—— 这是**唯一允许**主代理代行的场景
   - **flag 判定方法**（注：正常流程中 Agent 已在 spawn 规格第 0 条通过 `ToolSearch(query="select:Agent")` 加载成功，此处仅用于记录判定结果。若第 0 条加载失败才到此处判定）：
     1. 调 `ToolSearch(query="select:Agent")` 取 Agent 工具 schema
     2. 命中 → `no_spawn_env = false`（可用，后续按「显式等待 + 超时机制」执行）
     3. 未命中 → `no_spawn_env = true`，标记原因 `"Agent tool not in session tool list"`
     4. 判定结果写入 `adversarial_verification` 字段（`env_no_spawn` 或 `sync_ok`）
   - **flag = false 时硬禁止**（防误用）：**禁止主代理代行**！即使部分子代理未回结果（如 1/3 返回 verdict、2/3 超时），其余未回子代理应按上方「子代理失败处理」失败链路降级（标 `[未验证-子代理对抗失败]`），**不得"补齐"为代理代行**——这正是本轮（2026-07-29）实测踩坑
   - 代行时主代理在 §6 三个子章节写"主代理代行（环境无 spawn 工具）"+ 各自的独立判断，但**必须**：
     - 三个视角的推理各自独立（不得"证据也发现没问题、替代也没发现竞争解释、充分性也觉得够了"这种一致假共识）
     - 证据质疑者必须核对至少 3 条证据指针的原文（Read 实证）
     - 替代解释者必须提至少 1 个竞争解释（无 spawn 工具降标到 1）
     - 充分性质疑者必须列出至少 1 条"还缺的证据"
     - **与"自演"的区别**：主代理代行是"环境不允许独立子代理时的 best-effort 替代"——有 spawn 工具时绝不走这路径；无 spawn 工具时这是唯一可行方案，但必须标 `[未验证-环境无spawn工具]` 诚实告知用户
5. **留痕要求**：`adversarial_verification` 字段必须记录"环境无 spawn 工具，对抗按无 spawn 工具场景降级，附三视角主代理代行结果"

## 主代理实证 ≠ 自演（澄清边界）

主代理用 Read/Grep 查到的**代码/日志铁证**（如"某函数实际签名是 X"、"某行日志确实存在"）属于**事实核查**，不是对抗验证，**不算自演**。这类实证结论可走"实证快速通道"直接 `confirmed` 无需 spawn 质疑者（adversarial.md 各步骤分析对象段已声明）。

**真正必须独立 spawn 对抗的**是**判断性结论**——"这个设计合理吗"、"这个根因对吗"、"这个风险够不够"——这类没有铁证、依赖独立视角的判断，主代理自演无效，必须独立 spawn。失败时按上节"子代理失败处理"降级，不得自演。

## 裁决优先级（按顺序判定，命中即定，未命中进下一档；三档都不命中走兜底）

1. **`refuted`**：≥2 个质疑者判 `refuted`，**或**替代解释者给出被证据支撑的竞争解释且证据质疑者确认原证据失效 → 撤销，记入被推翻清单，写明推翻原因
2. **`needs_more_evidence`（一票降级）**：充分性质疑者判证据不足 → 降级进 `pending_verification`，标 `[未验证-证据不足]`，不计入 confirmed 清单（证据充分性是 confirmed 的前提，享有否决权）
3. **`confirmed`**：≥2 个质疑者判 `confirmed`（且未被前两档命中）→ 保留，计入最终清单
4. **兜底 `needs_more_evidence`**：以上三档均未命中（如三态分裂 `1 confirmed + 1 refuted + 1 needs_more`、或 `2 needs_more + 1 其他` 等）→ 降级进 `pending_verification`，如实记录"对抗未收敛"

> **为什么充分性质疑者一票降级**：`confirmed` 的前提是"证据充分支撑结论"。若充分性质疑者认定证据不足，即便另外两人判 confirmed，结论也站不住——此时确认等于伪造共识。故证据充分性享有否决权。
>
> **为什么需要兜底**：三人三态裁决可能出现无任何状态≥2票的分裂组合。兜底确保这类"对抗未收敛"的结论不会因规则漏洞被误判为 confirmed，也不会被丢弃——一律降级待验证。

## 早期收敛快速通道（省 token，第 1 轮可用）

**触发条件**（本轮为第 1 轮时判定，命中即收敛跳过后续轮次）：

1. 3 质疑者裁决**全部**为 `confirmed`（即裁决优先级命中第 3 档 `confirmed`）
2. 替代解释者的 `competing_hypothesis` **数量 = 0**（即未提任何新竞争假设）

→ **直接收敛**（跳过后续轮次）。

> **为什么不降能力**：3 视角独立看都通过 + 无新竞争假设 = 对抗已成立。固定跑满 4 轮是兜底不是越多越好。早期收敛是"足够即收"，不是"未审完就停"。
>
> **与裁决优先级的协作**：早期收敛是"裁决优先级跑完 + 全部 confirmed"后的"优化判定"，不是替代——只有当 4 档裁决全部走完且 3 票全 confirmed 时才触发。
>
> **第 2 轮及之后不触发**：早期收敛只对"全新分析"成立（首轮无历史结论兜底）；续跑轮次有历史对抗记录，必须走完整裁决流程。
>
> **省 token 原理**：典型场景（结论明确、证据铁证、无替代解释）从 2-3 轮降到 1 轮，子代理 spawn 次数 ↓~50%。

## 循环

分析师出结论（issue/根因假设 H + 证据指针 E + 置信度）→ 质疑者攻击 → 有实质反驳就修正/补证据/降级 → 重复直到收敛。

- **收敛判据**：所有质疑者一致认为成立 → 接受；达上限（默认4轮，可调）仍未收敛 → 输出"最强存活假设"，如实写明残余不确定性，**绝不伪造共识**；证据耗尽 → 同上诚实降级。

## 诚实底线

若 3 个质疑者对某条结论裁决严重分裂、无法形成多数意见，不得"和稀泥"默认 `confirmed`——必须降级为 `needs_more_evidence` 并在产出中如实记录"对抗未收敛"。**宁可降级，也不伪造共识。**

若证据不足以支持任何高置信结论，报告写"现有证据不足以定论，已排除 X/Y/Z，建议补充 W"。**宁可说不知道，也不编一个结论。**

## 证据回指纪律

每条 confirmed 结论必须能回指到**具体证据片段**（计划章节/代码 file:line/日志 节点+时间+原文）。做不到回指的结论不写进「核心结论」，只进「待验证假设」。

## 证据获取方法可靠性约束（防"间接推断当铁证"）

> **与「证据回指纪律」的分工**：回指纪律只约束"结论有没有证据回指"，本条约束**"证据是怎么来的、获取方法可不可靠"**——间接推断被当铁证是根因分析高频失误（如用 mtime 推断编译产物内容、`grep -c` 返回空当 0 命中）。

根因结论的每条证据必须标注**获取方法**：

- **直接观察**（日志原文行 / `strings <binary>` / `git show <hash>:<file>` 实际内容）——高可靠，可直接作铁证。
- **间接推断**（mtime 推断编译产物 / `grep -c` 返回空当 0 / 语义推测）——**必须标注推断链 + 不确定性**，不得直接作铁证。例：
  - ❌ "部署 build 含某诊断日志（源码 mtime 13:59 < 编译时间 14:40）"——这是间接推断，不能作"某日志 0 命中 = handler 没触发"的铁证（mtime 只能提示"可能含"，不能证明 build 实际内容）。
  - ✅ "部署 build 是否含该日志：间接推断 mtime < 编译时间提示可能含，但**未经 `strings <binary>` 或 `git show <hash>:<file>` 验证**，不确定性高。验证方法：`git show <deploy_hash>:<src_file> | grep <log_keyword>`。"

**反制规则**：间接推断的证据**不得单独支撑根因结论**；必须有至少 1 条**直接观察**证据交叉验证。日志 `grep -c` 返回空（非数字 0）时**不得当"0 命中"使用**，须换 `grep ... | wc -l` 或直接 `grep ... | head` 确认。

## 各步骤的分析对象

- **步骤2 review**：分析对象 = 步骤2.5 逐维审查产出的 issue（步骤2.4 实证验证失败的 issue 例外，已有铁证直接 confirmed 无需对抗）
- **步骤5 deepcheck**：分析对象 = Free 阶段 A6 深检/争议验证发现的 issue（必须独立 spawn 3 质疑者，详见 [05_deepcheck.md](../steps/05_deepcheck.md)「Free 阶段角度管理」段）
- **入口 log**：分析对象 = 阶段2 现场还原后分析师提的根因假设 H
