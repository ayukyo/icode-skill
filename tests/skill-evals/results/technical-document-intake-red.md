# RED：技术文档可信接入

## 执行条件

- 未加载待创建的 `technical-document-intake` 技能。
- 语料同时包含正常 PDF、标准 OOXML、受保护但后缀为 `.pptx` 的容器、扫描页、截断 7z、SDK 工具包、精确副本/修订变体和解析器运行库故障。

## 实际结果

基线代理主要按扩展名选择解析器，能读取部分 PDF 文本，但没有稳定输出逐文件 hash、magic 类型、逐页覆盖、工具身份、归档 header/成员风险、重复/变体分组和受保护状态。解析器启动失败时也容易混淆“工具不可用”与“文件损坏”，还可能把 7z 列目录或文件名“最新版”误当成内容完整和权威版本。

## RED 判定

**FAIL（可信接入合同缺失）**。需要独立 intake 层在语义分析前固定真实容器、证据身份、读取范围、安全边界和结论上限。
